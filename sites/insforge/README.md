# insforge.chenjin.io

面向 InsForge 用户的独立资源站架构骨架。正式域名为 `https://insforge.chenjin.io`，尚未绑定 DNS 或部署上线。

## 受众与内容规则

InsForge 是公司名，instacloud.com 和 insforge.dev 是旗下两个产品。访客是希望了解和使用这两个产品的用户。每项内容都应帮助用户判断产品变化，找到可用的示例，或完成具体的使用任务。

- 公司级团队动态统一记录，产品更新标明所属产品、用户影响与来源。当前两栏预览的动态入口尚未接入统一公司动态页。
- 用例给出使用场景、实现路径与结果。
- 实践包含步骤、适用条件和验证状态。
- 最佳实践与排错内容围绕使用问题组织。
- 个人增长经历、Launch 推广复盘和个人咨询推广留在主站。

内容可以由陈今编写，但选题和页面组织围绕用户需要。允许的内容类型与发布要求维护在 site.json，后续监听与内容录入必须沿用这些规则。

## 与主站的边界

- 独立的 Next.js 应用入口、构建命令和后续 compute/insforge 服务。
- 内容围绕产品使用组织。陈今的 Launch Week 1 增长复盘只保留在 chenjin.io，子站不收录，也不导流个人咨询。
- 禁止导入主站 src 中的页面、账号模块和私人数据。可复用的视觉资产以后提取为纯样式或无业务依赖的共享包。
- 动态监听和采集数据由子站自己的后端模块管理，按来源、审核状态与发布时间区分。
- 主站聊天记录与账号凭证不传入子站；登录 cookie 默认限定当前主机。子站将来需要登录时再明确认证接口。

## 开发

```sh
cd sites/insforge
npm install
npm run dev
npm run build
```

本地端口为 8085，当前生产构建预览为 `http://127.0.0.1:8085/`。独立构建和实际 HTTP/CSS 请求已通过。当前只展示面向用户的内容方向，预览页面暂不允许索引。主站构建不包含这个应用。

## 运行结构

```text
InstaCloud project chenjin-io
├── compute/web       → chenjin.io
├── compute/insforge  → insforge.chenjin.io
├── compute/growth    → growth.chenjin.io（应用待实现）
└── 子站监听任务与数据服务（后续按需要创建）
```

目前只建立代码目录，未创建这些云服务。已准备本目录的 Dockerfile、锁定依赖与独立样式构建配置。正式部署时从本目录生成独立部署产物，验证服务 URL 后再绑定子域名。主站和子站分别记录构建与发布证据。
