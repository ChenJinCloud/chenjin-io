# 课程地图

## 00. 先定义“个人网站”到底要解决什么问题

你不是在做一个电子名片，而是在做一个长期入口。第一步要回答三个问题：

- 谁会来看这个网站？
- 他看完以后应该更相信你什么？
- 他下一步应该做什么？

产出：

- 一句话定位
- 目标读者
- 主要行动入口

## 01. 搭建最小信息架构

第一版不要贪多。建议只保留 5 个区块：

- Hero：你是谁，你解决什么问题
- Proof：作品、经历、案例或可信信号
- Method：你的方法、观点或工作方式
- Offer：你现在开放什么合作或交流
- Contact：对方如何联系你

产出：

- 首页区块草图
- 每个区块的一句话目标
- 需要准备的素材清单

## 02. 写出第一版首页文案

文案先服务理解，再服务风格。每个区块都用“判断 + 证据 + 下一步”来写：

- 判断：你希望读者记住什么
- 证据：你凭什么这么说
- 下一步：读者可以点哪里、看哪里、找你做什么

产出：

- 首页 H1
- 3 条可信信号
- 3 个作品或内容入口
- 1 个明确 CTA

## 03. 初始化技术项目

推荐栈：

- Vite
- React
- TypeScript
- Tailwind CSS
- React Router

最小页面结构：

```txt
src/
  components/
    Navigation.tsx
    Footer.tsx
  pages/
    Index.tsx
    NotFound.tsx
  App.tsx
```

产出：

- 本地可运行项目
- 首页路由
- 基础样式系统

## 04. 实现首页

先实现内容顺序，再处理视觉细节。每个区块都要在移动端可读，按钮和链接要能点击。

最低标准：

- 首屏能在 5 秒内说明你是谁
- 每个作品入口都有标题、说明和链接
- 联系方式明显
- 移动端不溢出、不遮挡

产出：

- 首页可交互版本
- 桌面端和移动端自查截图

## 05. 部署和域名

上线不等于完美，但必须可访问、可分享、可回访。

部署步骤：

- 生成生产构建
- 部署到静态托管平台
- 绑定自定义域名
- 配置 favicon、标题、描述和社交分享图
- 检查 404 页面

产出：

- 线上 URL
- 自定义域名
- 上线检查记录

## 06. 建立后续迭代系统

个人网站最重要的不是第一版，而是它能不能持续接住新的作品和判断。

建议每月做一次轻量更新：

- 新增 1 个作品或文章入口
- 删除 1 段过时表达
- 调整 1 个合作或联系入口
- 记录 1 条访客反馈

产出：

- 月度更新记录
- 作品入口列表
- 下一版改进清单
